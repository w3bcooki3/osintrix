Osintrix product audit

Osintrix is a private, browser-only investigation workspace for OSINT analysts, threat researchers and CTF players. It is far more capable and polished than a typical proof of concept. It is not yet safe to call production-ready. The blockers are a handful of specific, fixable defects in data safety and the offline build, plus a code structure that will not carry the product much further.

Overall verdict

The product has a clear point of view: a private analyst workspace where nothing leaves the machine. It delivers real depth on that idea, including evidence capture with automatic indicator extraction across 25+ kinds, log parsing, a link graph that builds relations from what the evidence states, a hypothesis board, PCAP and SQLite readers, a file inspector, Sigma and YARA testing, and an encrypted workspace. The UI is consistent and careful, and the demo case is excellent onboarding.

The weaknesses sit in three places. Data safety: the app can silently overwrite a user's workspace, and two open tabs erase each other's work. Security of the offline build: its CSP allows inline script, so an HTML-injection bug becomes code execution. Scale and maintainability: everything is one JSON blob, one global namespace of 878 names, and full-page re-renders. The breadth has also outrun the information architecture, with 21 sidebar destinations.

What's strong

Preserve these and build on them.

  • Privacy architecture that matches the pitch. Strict CSP in index.html, no eval, a no-referrer policy, and every link passing through an http(s)-only safeUrl. Map tiles and live feeds require explicit consent.
  • Encryption at rest done properly. AES-256-GCM with a fresh IV per write and PBKDF2-SHA-256 at 310k iterations. Mirrors, restore points and attachments are all sealed, and only the theme and welcome flags stay in plaintext.
  • A pure extraction engine. engine.js is DOM-free and reused by capture, scratchpad, parser and search, which is the right core.
  • A safe archived-page viewer. It uses sandbox="", srcdoc and inherited CSP. Scripts, forms, navigation and remote CSS were all blocked in testing.
  • Evidence-first features. Graph links carry their reason from the evidence, suggestions must be accepted, and the "As of" slider replays how the case grew. These are differentiators.
  • Craft. Event delegation with no leaks over repeated navigation, capped long lists, lazy-loaded sql.js, synthetic demo data in documentation ranges, and tests that fail on any console error.

What's weak

  • Sprawl. 21 top-level destinations: Dashboard, Cases, Notes, Scratchpad, Toolbox, Query library, CTF, Forensics kit, Decoder, Cloud, Threat Intel, Watchlist, Detections, Entities, Reference, Playbooks, Security, What's new, Help, Settings, plus Pinned. The case, which is the unit of work, competes with a dozen side tools. Playbooks falls below the fold at 900px.
  • Code that resists change. 46 scripts share one global scope (878 names, 42 of them three characters or fewer) with implicit load order. Lines run long: p90 254 characters, 174 lines over 400, and some over 1,600. There are 44 empty catch blocks.
  • Persistence that doesn't scale. Every edit re-serializes the whole workspace. At 20k records that is a 14.6 MB string and about 135 ms of blocking per save. The promised localStorage mirror disappears past about 2.4 MB, which is already gone at 5k records.
  • Rendering by full rebuild. 199 renderMain() call sites. At 20k records the Vault takes 513 ms with 35k DOM nodes, and a timeline edit takes 512 ms. Search re-renders the page on every keystroke.
  • Layout overflow on desktop. At 1440px the graph toolbar is 1,649px inside a 1,188px space, and the Forensics kit tabs overflow too.

What's wrong

Confirmed defects, each reproduced with a script or in the live app. Severity reflects impact on a real user's data or machine.

CRITICAL
Stored data in an unrecognised format is silently replaced with demo data.

At boot, anything that isn't exactly v:2 with an entries array is treated as missing. The app then runs seedDB() and immediately calls flush(), writing the demo over both stores. A future schema bump, a partial write or a corrupted blob would wipe a user's investigation without warning.

core.js:31,40 · app.js:605,611 · reproduced with a v:3 marker blob
HIGH
Offline build turns HTML injection into script execution.

dist/osintrix-offline.html ships script-src 'unsafe-inline'. Injected onerror handlers run with the decrypted workspace in memory. Data can leave through the open rss2json relay allowed in connect-src, or through top-level navigation.

dist/osintrix-offline.html:6 · payload executed
HIGH
Unescaped values from imports reach innerHTML.

The context-menu title is interpolated raw (graph.js:157) and fed tool names and case codes from imports. Around 150 data-id="${id}" attributes interpolate unescaped ids, and backup import assigns DB = d with no schema check. Under the hosted CSP a crafted case file still produced a full-page phishing overlay; in the offline build it runs script.

graph.js:157 · app.js:199,219–232 · extras.js:120 · areas.js:15
HIGH
Two open tabs overwrite each other.

Each tab saves the whole blob, and nothing coordinates tabs (no BroadcastChannel, storage event or Web Lock). An analyst with the app open in two tabs keeps only the last tab's edits.

reproduced: rename in tab A lost after save in tab B
MEDIUM
Pasting crafted text freezes the app.

The email, host:port and domain regexes are quadratic. A string like a.a.a… took 0.8 s at 16k characters, 3.3 s at 32k and 34 s at 100k, with the UI frozen. That input is easy to hit by accident in a log paste.

engine.js:92,94,102 · timed in page
MEDIUM
A case import can overwrite another case's evidence files.

Imported files are written to file:<id> with no collision check, and stored hashes aren't re-verified. Separately, the attachment viewer picks its safe mode from declared metadata but opens the real blob type, so a "PDF" that is HTML opens as HTML.

safety.js:144–156
MEDIUM
The audit chain and custody signature promise more than they prove.

The chain is unkeyed SHA-256, so deleting an entry and rehashing verifies as intact. Custody verification checks the signature against the public key embedded in the same report, so a re-signed forgery shows "Signature valid". The signing key also travels in unencrypted backups.

security.js:119–157 · forgery reproduced
MEDIUM
Graph layout blocks the page at realistic sizes.

With 2,018 nodes and no saved positions, the cose layout (1,500 iterations) froze the main thread for 40.9 s.

graph.js:68
MEDIUM
Accessibility gaps.

An axe-core pass over six screens found 181 contrast failures and 106 nested interactive controls (Toolbox rows are role=button containing buttons). It also found 70 scrollable code blocks that keyboard users can't focus, and 33 invalid aria-selected uses.

LOW
Smaller correctness issues.

The dashboard labels the all-time record total "captured this week" (views.js:54). The Timeline tab says 21 while its filter says "27 of 27". The KDF iteration count is read from stored or imported data and can be lowered. Unreferenced files stay unencrypted. The failing test whitelists Chromium's old CSP message wording (tests/helpers.js:10).

What's missing

  • Schema versioning and migrations. There are about 12 boot-time ensure*() patches and nothing else. The app needs a version, ordered migrations, and a "this data is newer or damaged, here's a raw export" screen instead of reseeding.
  • Import validation. Case, backup and tool-list imports need a schema check, id escaping and re-iding of files on import.
  • Multi-tab safety. Use a Web Lock with a "this workspace is open in another tab" read-only mode.
  • A worker boundary. Extraction, parsing, YARA and Sigma tests, and graph layout should run off the main thread with input caps.
  • Honest integrity claims. Either key the audit chain and require an out-of-band key fingerprint, or describe it as an edit log rather than tamper evidence.
  • Durable storage outside the browser. Optionally save to a user-chosen folder with the File System Access API, so a cleared browser profile isn't the end of a case.
  • Test coverage where the risk is. Backup and import round-trips, schema handling, multi-tab use, global search and the YARA/Sigma engines are currently untested.

What's unnecessary

  • Dead and dangerous files. build.py overwrites the live index.html from a stale src/ fork. Also remove the duplicate vendor/cytoscape.min.js and _old-single-file/. The changelog already says these are gone.
  • Four version sources. package.json says 1.6.0, while brand.js, changelog.js and 57 ?v=1.15 query strings say 1.15. Keep one.
  • Top-level nav for low-frequency pages. What's new, Security, Cloud and CTF don't need permanent sidebar slots. They belong in Settings, the Kit or the command palette.
  • About 1.8 MB of eager vendor code. The OUI table, Cytoscape, Leaflet with the world map, jsQR and js-yaml can use the existing lazyScript().
  • README drift. It claims 68 queries (there are 70), and the CI workflow and docs screenshots it references are absent.

Three design proofs of concept

Each concept is a working prototype built on the real Op Lantern case: real records, indicators, verdicts and the cross-case IP. Each takes a different position on the product's core question: what should an analyst look at most of the time?

A · Casefile

Reading-first. Three panes: cases, the evidence itself, and a dossier for whatever indicator you select.

The raw evidence is the primary surface. Indicators are marked inline like a highlighter on paper: yellow for new, red for malicious, grey for internal. Clicking one filters the reader and opens the dossier with verdict, sightings, other cases and lookups. The Toolbox, Decoder, File inspector and Reference move into a "Kit" opened from any case. Capture checks indicators against every case as you type. Public Sans and IBM Plex Mono on a cool paper neutral, with the highlighter as the only bold element.

Stronger

  • Matches the actual workflow: read, mark, judge, pivot
  • Cuts the nav from 21 destinations to cases plus a Kit
  • Smallest change from today's main pane and inspector

Weaker

  • The graph becomes a secondary view
  • Less striking in demos

Best for: SOC and IR analysts and OSINT researchers doing evidence-heavy casework, which is the core audience in the README.

B · Pinboard

Graph-first. The investigation is the board; everything else floats over it.

A full-bleed canvas in a dark slate palette, with verdict colour on node rings and dashed red edges where a case crosses into another. Pivots sit in a radial menu around the selected node. The bottom bar is a time scrubber with evidence ticks that replays how the case grew, which promotes today's "As of" slider into the main navigation. Set in Barlow, with semi-condensed labels for dense node text.

Stronger

  • The most distinctive and memorable concept
  • Excellent for attribution and briefing
  • Makes "look at next" and cross-case links unmissable

Weaker

  • Poor for reading long logs
  • Inherits the 40 s layout problem at scale
  • Hardest on phones

Best for: threat-actor attribution, infrastructure mapping and presenting findings.

Open the Pinboard prototype

C · Console

Keyboard-first. A command line drives everything, with dense split panes and a status line.

One grammar covers the app: host:WS-FIN-07 tag:c2 filters, while pivot, set, decode and capture act. Tokens are parsed visibly as you type. Indicators are colour-coded by kind, like syntax highlighting, with a wavy red underline for malicious. You move through records with j and k, and the status line shows case, counts and encryption state. Set entirely in Martian Mono on graphite.

Stronger

  • Fastest for experts; scales to large datasets
  • The grammar already half-exists in global search
  • Cheapest to render: tables, no layout engine

Weaker

  • Steep for newcomers and occasional users
  • The least visual for reporting

Best for: CTF players, blue-team power users and anyone living in logs.

Recommendation: adopt A, Casefile, as the product's backbone, and borrow one signature idea from each of the others. Take B's time scrubber and "look at this next" card into the Links view, and C's filter-and-command grammar into Ctrl K. Casefile puts the analyst's main activity, reading evidence and judging indicators, at the centre. It resolves the navigation sprawl and is the cheapest to reach from the current main-pane-plus-inspector layout.

Production readiness

Osintrix should not be promoted as production-ready until these are fixed. Each one breaks the product's own promise that your cases are safe in your browser.

  • The silent reseed path can wipe a workspace.
  • Multi-tab use loses edits.
  • The offline single-file build executes injected script.
  • Imports are trusted without validation, and shared case files are a realistic attack path in this domain.
  • The integrity features are described as stronger than they are.

None of these needs a rewrite. The first four are days of work, not weeks.

Method and limits

Everything above comes from the v1.15 source in the project folder. The app was run from disk in Chromium 1.63 at desktop and phone widths, and the bundled Playwright suite was run. The security findings were reproduced with targeted scripts. Scale tests used synthetic workspaces of 5k and 20k records, and accessibility was checked with axe-core. I did not test the hosted GitHub Pages build, Firefox or Safari, real-world RSS feeds, or very large PCAP and SQLite files. I made no changes to the app's code; the prototypes and this report sit in a separate design-pocs folder.
